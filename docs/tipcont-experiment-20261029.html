3 · Why the 0.2778 file scored highest, and what we can measure

  • Measured (this repo): GEMSDOE32 B2 is exactly the GEMSDOE31 h27-4-solo-d28 file minus 2,545 dots (B2 is a subset of that base: True). All removed dots lie 141–200 m from the catalogue. B2 has 37,654 binary dots, none on the USGS/INGENIOUS catalogue and 0 within 200 m (its nearest dot is 224 m away). Its outside convention is zeros, and a NaN twin with identical dots is also published. Share of dots within 200 m of the catalogue: GEMSDOE32, GEMSDOE36 at 0.0%; the other 7 files range from 6.2% to 14.6%.
  • Hypothesis, not proven: the metric charges false positives at 0.2 and false negatives at 0.8. Dots within 200 m of a mapped fault mainly duplicate structure that is already mapped, and the hidden labels are new faults, so those dots add false-positive weight. The only difference between B2 and its base is that removal, which is measured. The score difference is not: the 0.2708 attribution for the base is flagged as unsupported by the owner's own forensic note (GEMSDOE33 repo, knowledge/01_why_0.2708_won.md), and AGENTS.md states the top six sites are statistically tied. The 0.007 gap is therefore within noise and unverified.
  • Not established: whether any file can beat 0.2778 on the organizer's private set. The leaderboard leader is 0.4544 on the live page.

6 · Irregularities flagged for review

  1. Leaderboard top value differs across sources: prompt lists 0.4413 and 0.3195; the live DrivenData page (fetched 2026-10-29) shows #1 0.4544 and #2 0.3916.
  2. AGENTS.md described WBG-6 as APPROVED; its own audit fails the literal 70% gate (3 px overlap 0.99677 vs r13-lattice-s5). Corrected in this session.
  3. GEMSDOE25 and GEMSDOE30 top files have identical positive pixel sets (44,090 dots, all shared) though listed as separate sites, both at 0.2600.
  4. Portal error 'Predicted values must be in range [0, 1]' is unexplained. The official text allows null or NaN outside the footprint; the shared writer defaults to zeros on an unverified claim that NaN is rejected.
  5. The 0.2778 value is USER-REPORTED. No organizer receipt for that file exists in the sources reviewed.
  6. The GEMSDOE32 audit calls B2 a prune of a '0.2708 base'. That base is measured as the GEMSDOE31 h27-4-solo-d28 file (40,199 dots), but the GEMSDOE33 repo's forensic note says the 0.2708 file association is unsupported: no organizer receipt, and the GEMSDOE28 owner page labels H27-4 unscored.
  7. training_features.tif (about 419 MB) is not in the repository and DrivenData requires login; no holdout uses the full feature stack.
  8. The shared holdout collar (15 px) withholds only truth at least 15 px from visible faults. Rays up to 15 px from a visible tip are structurally unable to earn credit. Flagged for review; the shared evaluator was not redesigned.
  9. The literal 70% gate is degenerate against dense lattice rasters: the 206,895-dot r13-lattice-s5 overlaps the new file at 99.9%, where chance expectation is 69.4%.

7 · Limitations

  • No organizer score is available for any file in this repository. Every number here is a HOLDOUT-DTI, USER-REPORTED, or a measured local property.
  • The sandbox cannot reach DrivenData, Dropbox, OpenEI, or the NLR PDF directly. The official rules were read through the page-fetch tool. GitHub and PyPI were reachable.
  • Holdout uses catalogue segments as stand-in truth. The competition's hidden labels are NEW faults that are not in the catalogue, so a catalogue holdout does not measure the competition target.

8 · Next steps (ranked)

  1. Obtain authenticated access to training_features.tif and the DrivenData data tab (login required). Without it no holdout can use the full feature stack.
  2. Use one weekly slot only after a passing holdout and a lane-unique file. A portal format test costs a slot, so decide that explicitly.
  3. Test a distinct mechanism (for example, a feature-based scarp or magnetic lineament detector) against the full feature stack. Stop the lane if overlap exceeds 70% with any of the 754 binary registry rasters.
  4. Ask the holdout owner to review the 15 px collar, which makes near-catalogue hypotheses untestable.
