Step-by-step submission

  1. Download the TIF (or one-TIFF ZIP) from the card above.
  2. Verify locally with the project validator (no upload, no auth needed):

  docs/downloads/WBGGEMSDOE1-blind-zone-ring-220-0m-120-0m-20261028-d63a12ef423e-zero.tif
    Every hard check must pass: single band, float32, EPSG:32611, 3730×3292, exact geotransform, values in [0,1], no NaN/inf, zero outside footprint, zero dots on catalogue.
  3. Record the metadata:
    • Name: WBGGEMSDOE1-blind-zone-ring-220-0m-120-0m-20261028-d63a12ef423e-zero
    • Note (≤140 chars): WBGGEMSDOE1 blind-zone-ring-220.0m-120.0m | unique blind-zone ring emission, catalogue-blind Poisson | id d63a12ef423e | not yet live-scored
    • SHA-256: a8f3d754c07f89e40021902f9ab6c21e505e13660829d983c3cfef80b48e8b8f
  4. Upload the single-band .tif (or a ZIP containing exactly that one TIFF) at the official DrivenData submissions page (login required). Paste the short note. Respect the weekly entry limit shown on the page.
  5. Keep the organizer receipt. Store the submission ID, exact artifact SHA-256, time, note and copied result. Only then label the result ORGANIZER-CONFIRMED. The public leaderboard alone does not identify your file.

What the automated preflight checks

No human inspector — every check runs in code.

  • One float32 raster band, values in [0,1] and no NaN/inf anywhere (conservative all-finite export policy)
  • CRS EPSG:32611, shape 3,730 rows × 3,292 columns, 100 m pixel grid, exact reference geotransform/bounds
  • Zero support outside the mirrored footprint
  • Zero dots on mapped catalogue faults
  • On-disk roundtrip plus a ZIP containing exactly one identical GeoTIFF
  • SHA-256 recorded before upload so the organizer receipt can be matched to the artifact

The official format says data outside the bounds should be null/NaN. All-finite zeros outside the mirrored footprint are a conservative local project choice. Local validation does not establish organizer acceptance; only an organizer submission receipt does.
