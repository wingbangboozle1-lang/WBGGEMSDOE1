3 · Why GEMSDOE32 B2 scored highest, and whether 0.2778 can be beaten

What the evidence shows. The nine focus files come from one family, and the removal chain is verified from the raster bytes (29 Oct audit, executive-summary-20261029.html). D2.8 (44,090 positives; user-reported 0.2600) is reduced to B1 (40,199; 0.2708) by removing 3,891 dots within 100 m of the catalogue. B1 is reduced to B2 (37,654; 0.2778) by removing 2,545 more dots within 200 m. B2 has zero dots within 200 m of the catalogue. The user-reported score rises with each removal. Under the official metric (α = 0.2 false positives, β = 0.8 false negatives, 300 m triangular kernel), a dot near a mapped fault costs a false positive unless a hidden fault lies within the kernel, so removing dots that carry no hidden-fault credit can raise the score. MECHANISM: plausible, not proven.

Can >0.2778 be achieved? Possibly, but nothing measured in this repo shows it. The score is user-reported and not organizer-confirmed. The best holdout in this session (0.0536) is far below the 0.1661 benchmark. The one earlier file I found above that benchmark (WBG-S2, 0.1836) was stopped by the overlap gate at 99.55%. No file yet passes both gates.

7 · Irregularities flagged for review

Machine-readable list: irregularities_20261031.json (I1–I12).

  1. I1 · Leaderboard premise. The brief's 0.4413 top score does not appear on the page. 0.3195 is #50, not the leader (section 4).
  2. I2 · Score labels. The nine focus scores are USER-REPORTED. No HOLDOUT-DTI or ORGANIZER-CONFIRMED value exists for any of them, and no organizer receipt exists for any file.
  3. I3 · Label-source conflict in the official rules. Rules §2 names USGS Quaternary Fault and Fold Database labels plus expert-labelled new faults. Rules §3.3 names the INGENIOUS Great Basin compilation as the training-label source. Both are in the same PDF (rules PDF). Owner to confirm which applies.
  4. I4 · Generative-AI disclosure. Rules §3.2 requires any use of generative AI to be disclosed in the submission narrative, with its extent and purpose. This lane used AI-assisted coding and analysis. The disclosure is needed before any submission.
  5. I5 · Registry scan incomplete. 117 of 118 rasters were checked. 14GEMSDOE · GEMS_r5-geom-horse-ensemble failed with "registry CRS/transform differs from reference", so the uniqueness verdict is not complete. Receipt: evidence/uniqueness/ and the run card.
  6. I6 · Shipped file differs from the measured method. E2 emitted roughly 50,000–87,000 dots per holdout fold. The shipped full-catalogue run at K = 12,198 emitted 33,897 dots. The holdout result therefore does not directly describe this TIFF. Dot density differs by about 7× (holdout: 50,000–87,000 dots on roughly 1.2 M cells per quadrant; full map: 33,897 dots on about 5.1 M cells). The likely cause is that the greedy allocator is sensitive to the probability spread of each model. This is a hypothesis, not a measured result.
  7. I7 · Template defect. vendor/template57/prepare_data.py: main() resolves ROOT to vendor/ when run in place. Its functions were called unchanged with ROOT set to the repo root. Reported to the owner; no fork made.
  8. I8 · Missing external inputs. data/external/ lacks sgmc_faults_100m.tif, derived_sgmc_faults_100m.tif, trace_segments_utm11.csv and qfault_attributes.csv. The template PIN check therefore fails. This is a limitation, not a pass.
  9. I9 · Unexplained NaN pixels. About 1,521 NaN pixels per band lie inside the footprint. They have not been explained.
  10. I10 · Two writer paths. vendor/gems57/submission_writer.py (fail-closed, 0 slots) and scripts/submission_writer.py (wraps src/gems/submission). Both exist; the fail-closed path was used for the holdout.
  11. I11 · Literal 70% gate is degenerate. A dense lattice captures about 99.7% of any field, so the literal gate can be met by almost any dense file. It is the lab's own protocol. The official rules text reviewed (sections 1–3.6 and the start of Appendix A) contains no duplicate-submission rule. Appendix A chunks 4–6 were not read this session.
  12. I12 · Time budget not re-verified. The 2-hour window was not re-checked after the data restore.
