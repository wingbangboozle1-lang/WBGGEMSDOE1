Why WBG-H1 avoids the “[0,1]” error you saw: The competition portal runs a strict whole-array check: every pixel in the 3,730×3,292 raster must be finite and ∈[0,1]. Many historical files (GEMSDOE25, G28, G30, G31, G24, G27) store NaN outside the GeoDAWN footprint to save bytes; the portal rejects those as “not in [0,1]” because NaN fails the range test. WBG-H1 is exported with outside="zero" · nodata=None — strictly 0.0 outside, 1.0 on dots, 0 elsewhere — so 0 NaN / 0 Inf across all 12,279,160 cells. This was verified by reopening the exact bytes on disk (see validator receipt).

Five steps to a valid submission (automated checks — no human inspector)

1 Confirm the master table decision

Open Executive summary → Master decision table. Only the green PASS row (WBG-H1 EXP-3) is both portal-valid and unique. Every other generated or historical file is marked NO — do not submit with a measured reason (overlap FAIL, NaN exterior, family duplicate, etc.). Do not select a file solely by its old leaderboard claim.

2 Check your weekly allowance (do not store credentials)

The official rules PDF §3.4 states up to three entries per week as specified on the website. The submissions page (login required) shows your actual remaining allowance. It currently redirects to login, so remaining allowance is reported as unknown in this static site. Never paste a password, API key, or token into chat or a git commit.

3 Download the exact bytes — do not re-encode

Use the link above (TIF or one-TIFF ZIP — both are accepted per the problem specification). Save it locally exactly as downloaded. Do not open and re-save in QGIS/GDAL/Python with default compression or nodata changes unless you re-validate afterwards; re-encoding can introduce NaN or alter the transform.

5 Upload on DrivenData and retain the receipt

Go to the New submission form:

  1. File to submit: choose wbggemsdoe1-wbg-h1-dpgf1-exp-3-20261026-0749b3c8195f-zeros.tif (or the ZIP). The form accepts .tif or .zip containing one GeoTIFF with the submission CRS/shape/transform.
  2. Note (optional) — paste exactly: 
    WBGGEMSDOE1 WBG-H1 (EXP-3): DipShift+TFSDI+DualLiDAR+CELF300m; HOLDOUT-DTI=0.1233 vs B0=0.1039; 37654 zero-ext dots
    This ≤140-character note identifies hypothesis, holdout result, and dot budget for your records.
  3. Submission name: wbggems1-dpgf1-exp-3-20261026-0749b3c8195f (auto-derived; do not invent a new one).
  4. Click Create and wait for organizer processing (no instant score; leaderboard updates after evaluation).
  5. Store the receipt: submission ID, SHA-256, timestamp, note, and the copied result from the submission page. Only then may you label that result ORGANIZER-CONFIRMED. The public leaderboard alone does not identify your file. The rules require one final selected submission across both prize rounds.

After upload, document the outcome: Copy the result text back into this repository’s evidence (do not alter the TIFF bytes) so future sessions can distinguish HOLDOUT-DTI from ORGANIZER-CONFIRMED without confusion.

What “validated without human intervention” means here

Every file on this site was validated by code that reopens the exact on-disk bytes and checks: one float32 band, EPSG:32611, 3,730×3,292, 100 m grid, exact geotransform, no NaN/Inf anywhere under our conservative outside="zero" policy, values ∈[0,1], zero support outside the footprint and on the catalogue. A human inspector is not required — and cannot waive — these gates. A “format PASS” is not a scientific win, a uniqueness pass, or organizer acceptance; it simply means the portal’s first-line check will not reject the file with “[0,1]”. Our selector verdict (negative for both lanes) is a separate scientific/uniqueness gate: we do not spend a weekly slot on a file that trails the current best holdout (DPRF1 0.1638_holdout) or that is a near-duplicate of a known lattice, even if it is technically uploadable.
