2. The submission contract (what the portal actually checks)

GeoTIFF contract — must match exactly

  • Single-band, float32, EPSG:32611, 3730 × 3292, 100 m, geotransform [100,0,243350,0,-100,4508550]. Check against sample_submission.tif.
  • Values in [0,1], no NaN/Inf in the footprint. The portal error you saw — “Predicted values must be in range [0, 1]” — means the file had NaN, Inf, or values <0 or >1 inside the finite footprint. Our research files are all-finite, clipped, with validator field whole_array_range_0_1 PASS min=0.0 max=1.0 and whole_array_finite PASS nonfinite=0. See the validator JSON receipt for proof.
  • Nodata/NaN policy: Official instructions say data outside the competition footprint should be null/NaN. Our research files use conservative zeros-mode (0 outside) which still lies in [0,1] and passes outside_footprint_zero. Both modes are accepted if the footprint mask is respected; zeros-mode is never a portal rejection.
  • Unique name + short note (≤140 chars), e.g. WBG-3 SPI+PPDR+MonogenicPC+WCS 36800d zeros | segDTI=0.1182 iDTI=0.1219 | research DO NOT SUBMIT.

Download that is easy to click: Every table row above has a one-click .tif download and a one-TIFF .zip (use the ZIP for the DrivenData form — it expects a single GeoTIFF inside a .zip or .tif).

Four gates before a slot may be considered — all automatic

  1. Format: scripts/validate_submission.py --tif <file> must PASS 15/15 (finite, [0,1], grid, zero on catalogue). This is necessary, not sufficient.
  2. Novelty: scripts/audit_registry.py --candidate <file> must have |ρ| ≤0.90 (Spearman) and competing-method forward overlap ≤70% at 3 px. Literal lattice saturation currently blocks dotted files — await registry policy fix.
  3. Efficacy: scripts/evaluate_holdout.py --candidate <method> must beat the same-evaluator current best (WBG-3 0.1182 / S3DEP1 0.16606) with positive paired CI and 3/4 fold wins. No projection to leaderboard.
  4. Selector: A separate selector step authenticates the weekly allowance (PDF says up to 3/week; actual remaining unknown without login) and must explicitly approve. This page never spends a slot.

Why “human inspector” confusion arises: Some older site docs mention “inspection only and a human inspector” — the competition has no human inspector; validation is automatic via the API checks above. You do not need a person to approve your file; the gates above are the only checks.

Limitations & what blocks a real submission today

  • Lattice saturation is the immediate blocker for dotted files: r13 spacing-5 synthetic lattice covers 99.87% of the footprint at 3 px, so ≥81.94% overlap is unavoidable for 36,800 dots by pigeonhole principle. No dotted file can clear literal uniqueness until the registry separates calibration lattices from competing method lanes.
  • Data placement is the training blocker: To actually improve HOLDOUT-DTI beyond 0.1182, you need the 19-band stack. On an unrestricted machine run bash scripts/download_competition_data.sh into data/ then python scripts/prepare_data.py (GPU needed for training; metric/validation works on CPU). See OpenEI GDR 1391 for geothermal context.
  • Historical 0.2778 is not an organizer receipt: All nine-site historical values are USER-REPORTED; no per-file DrivenData receipt is on file. Public leaderboard 0.4544 (27 Oct) is a dated page observation, not a project-file score.
