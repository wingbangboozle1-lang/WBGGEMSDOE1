00 / WHY 0.2778 IS THE SITE BEST, AND WHAT BEATING IT COSTS

One identity explains the whole plateau.

For a dot field whose dots are more than 2R+1 = 7 px apart, no two dots can claim the same hidden truth cell, so FPw = N − A where A is each dot’s own best kernel credit and FNw = K − TPw. The organizer metric then reduces to

DTI = TPw / (0.2 N + 0.8 K + 0.2 (TPw − A))

Verified against the canonical implementation, our shipped field scored against labels.tif as a proxy truth: exact 0.014296 vs naive 0.014309. The 0.2(TPw − A) correction is real — one dot can be the best claimant of several truth cells — but it is under 1% of the denominator here, below the registry’s own 0.0175 noise floor, so the naive form is used throughout with that error bar attached.

TPw cancels out of the denominator to that accuracy: score is linear in claimed credit and every extra dot costs a fixed 0.2 of denominator — which is also why the shared allocator's accept bar has the shape it has. Beating 0.2778 needs more credit at the same count, not a different map of the basin.

03 / WHY 0.2778 WON, AND WHAT BEATS IT

PhD-level reading of one deletion and 63× swing.

  1. The metric, from the official problem page (verified 2026-10-31 02:21 UTC). TP_w = Σg maxx p(x)k(d), FP_w = Σx: p>0 p(x)[1−maxgk(d)], FN_w = |G|−TP_w, DTI = TP_w/(TP_w+0.2 FP_w+0.8 FN_w), triangular kernel k(d)=max(1−d/3px,0). Because FN carries weight 0.8 and FP only 0.2, and because TP is capped at 1 per truth cell while every dot pays 0.2, the score is dominated by how many dots land on unseen truth and how few are wasted.
  2. Algebraic consequence. DTI = T / (0.2 T + 0.2 FP + 0.8 K). A dot is worth adding only while its expected credit exceeds α DTI/(1+α DTI) ≈ 0.05 at these score levels; below that bar each extra dot lowers the score.
  3. What the 0.2778 file actually did (measured, byte-verified in this repo). It added no detections at all: it is a strict deletion-only subset of the 0.2600 GEMSDOE25 field, with exactly 6,436 dots removed and every one of them within 200 m of the public catalogue (evidence/h33_b2_forensics.json). Under the algebra above, deleting guaranteed false positives at unchanged TP raises DTI: that is the whole mechanism.
  4. Two controlled confirmations in the same portfolio. The same 44,090-dot field scores 0.2600 off-catalogue and 0.0041 when it is buffered onto the catalogue (gems81-cont-poisson44090-buf2) — a 63× swing from catalogue proximity alone. Across all 118 files the monotone pattern is that score falls as the fraction of dots within 3 px of the catalogue rises.
  5. Why nobody there broke 0.28. All nine focus sites sit in one plateau (0.2449–0.2778) built from the same emission template (18 of 118 scored rasters carry exactly 37,654 dots, 7 carry exactly 44,090). They differ in the geology they cite, not in what they emit. Pruning to the marginal bar — and then ranking better — is the only lever the registry leaves open, and the public leaderboard shows the prize for taking it: 0.3417 is rank 20 and 0.4544 is rank 1 as of 2026-10-31T01:12:00Z.

08 / IRREGULARITIES FLAGGED FOR REVIEW

Things that do not add up, stated plainly.

  • the owner brief quotes three different 'current best' values (0.4413, 0.3195, 0.4544); the official public page read on 2026-10-31 shows 0.4544 at rank 1 &mdash; the brief is stale
  • no file in any sibling site carries an organizer receipt in this repo, so all nine 'scores' are OWNER-REPORTED and can be wrong; near-identical rasters differ by up to 0.086 (evidence/score_consistency.json), which is larger than the whole 0.26&ndash;0.28 plateau gap
  • labels.tif and existing_faults.tif are byte-identical (sha256 7ba308cc&hellip;), so the competition ships no training signal for <em>unmapped</em> faults: the model target and the scoring target are different populations
  • sample_submission.tif is described officially as 'total fault absence' yet contains the 60,988 catalogue cells (IR-31-TEMPLATE-CATALOGUE-CONTENT); training on it as a zero-annotated template would teach the catalogue, not absence
  • 18 of 118 scored rasters carry exactly 37,654 dots and 7 carry 44,090 &mdash; the nine 'independent' sites are one template family
  • the official band metadata calls band 15 'depth to base surf &mdash; depth to basement surface'; the problem page calls the same product a top-of-crustal magnetic source depth estimate &mdash; the wording differs, the derivation does not, and both are used in sibling write-ups as if they meant sediment thickness
09 / LIMITATIONS AND NEXT WORK

What is blocking a top-5 place, and the order to attack it.

  1. run the WBG-8 estimator against a <em>real</em> receipt: one authorized upload of the cleared file turns every number on this page from MODEL-ESTIMATE into a calibrated check
  2. replace the catalogue-proxy holdout (documented as non-ranking) with the registry-inverted estimator as the primary screen, and keep the holdout only as a leakage check
  3. test H3/H4 with the free official external data: GEODAWN radiometrics (https://www.usgs.gov/data/geodawn-airborne-magnetic-and-radiometric-surveys-northwestern-great-basin-nevada-and) and the INGENIOUS fault package (https://gbcge.org/current-projects/ingenious/); both are obtainable, neither is yet cached in this repo
