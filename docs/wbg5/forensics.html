01 / FORENSICS

Why did h33-h33-2-b2-…-e5eb6e7e-zeros score 0.2778?

Because of what it deleted, not what it found. The metric is DTI = TPw / (TPw + 0.2·FPw + 0.8·FNw) with a 300 m triangular kernel. B2 is an exact subset of the D2.8 field: it removes 6,436 dots and adds none. Every removed dot lay within 200 m of the public catalogue (3,891 within 100 m, 6,436 within 200 m). The organizer has stated in writing that pixels on known faults are masked out of scoring, so a dot sitting on a mapped fault earns nothing — while a dot 100–200 m off it sits in an unmasked pixel and is charged the full false-positive price. Deleting that ring lowered the FP term and the reported score moved 0.2600 → 0.2778 (+0.0178). That is a precision-cleanup mechanism, not a new discovery.

The same arithmetic caps the whole family. Differentiating the metric, one extra dot at kernel weight k raises DTI exactly when k > 0.2·DTI (exact, because 1 − α − β = 0 makes the denominator move by exactly α) ≈ 0.056 for DTI ≈ 0.28. In words: a dot within ~2.8 px of an unseen fault is always worth emitting, and a second dot on a fault that is already covered is worth nothing. Coverage of distinct truth pixels is the objective; ranking pixels by probability is not.

So yes — 0.2778 is beatable, and the route is placement plus off-catalogue physics. Two measured facts support that. (i) At an identical budget of 55,000 dots, spacing-constrained coverage beats top-k ranking by a factor of ten on the holdout (0.0648 vs 0.0064). (ii) The catalogue-aware arm collapses into a catalogue copier — 100.00% of its high-confidence pixels lie within 3 px of a mapped fault, which the organizer masks — so the only arm that can add score is the physics-only one, which is what this file uses.

Empirical refutation of the naive mapping: GEMSDOE32 B2 (owner-reported 0.2778, the highest) measures HOLDOUT-DTI 0.0067, while the lower-scored d1.5 file (0.2477) measures 0.1718. The ordering inverts, so a monotone transfer assumption is refuted by our own two flagship anchors.

Why that is expected: The holdout scores recovery of mapped faults. The organizers mask mapped faults out of scoring in writing, so a submission's catalogue recall is worth nothing on the leaderboard. B2 deleted exactly the near-catalogue dots that the holdout credits, and its reported score rose - which is consistent only if those dots were earning nothing on the leaderboard.

What would make the leaderboard score estimable: ['Two submissions with organizer receipts on the same artifact family.', 'The public-test fault labels (not published).', 'Or an explicit statement that the public score and the holdout share a monotone map.']

03 / HYPOTHESES

Five candidates, ranked by expected gain per unit of cost

Rank 1 is implemented and measured in this file. Ranks 2–5 are pre-registered and untested; each names the free, official source it needs.

  1. Saturating coverage placement on a physics-only likelihood surface — the implemented one. Layers: 11 LiDAR scarp-morphology channels, 4 radiometric (K, Th, U, TC), 4 magnetic (ThK, UK, UTh, TMI up-150 m), 8 structure-tensor/gradient channels, 6 terrain aggregates. Signature: scarp morphology (slope excess, crest convexity, uphill-facing step) plus cross-cutting lineaments in magnetics and radiometrics. Why off-catalogue: the features are terrain and geophysics, so a mapped fault is not a positive by construction — the model has to re-find the physical signature, and pixels on the catalogue are masked at scoring anyway. Cost: 1 model, ~10 minutes on 2 CPU cores. Status: measured below.
  2. Thermal-flux corroboration gate — only emit where a fault-likelihood ridge coincides with an independent geothermal manifestation (wells/springs). Needs the USGS/GDR well and spring inventory (free, already fetched as gdr_wellspring_in_footprint.csv). Expected: small DTI gain, large precision gain on the Final Round, because it is the mechanism the sponsor cares about. Cost: low. Status: not yet validated.
  3. Cross-strike dilatation vs scarp-asymmetry non-coaxiality — where the near-surface scarp faces the opposite way to the strain-rate dilatation gradient, the scarp is probably not a fault scarp. Needs the organizer's strain-rate bands from training_features.tif (login-gated; not present in this checkout). Cost: medium, blocked on data. Status: blocked.
  4. Basin-fill magnetic-depth closure — top-of-magnetic-source depth steps across a basin margin mark buried faults with no surface scarp. Needs the organizer's magnetic-depth band (login-gated). Cost: medium, blocked on data. Status: blocked.
  5. Road/mine-bench suppression as a negative-control channel — the honest answer to the named non-fault mimic (TIGER roads and BLM claim boundaries produce the same LiDAR steps). Cost: low. Status: the product is mirrored at data/external/audit_sources/tiger_road_distance_m.tif but is not hash-pinned, so it was not used in the promoted file to keep provenance strict.

05 / IRREGULARITIES FOUND

One gate in this repository was mathematically vacuous

Earlier lanes were frozen for “>70% of dots within 3 px of a registry raster”, where the registry raster was 13gems_20261001_r13-lattice-s5 — a synthetic 5-pixel lattice. Measured on the bytes: 99.871% of every pixel in the study area is within 3 px of a lattice node, and a uniformly random set of 40,000 dots scores 0.9987 against it. Any submission whatsoever fails that gate, so the gate carried zero information about copying. This lane keeps the number in the record, labels it vacuous_by_construction, and applies the duplicate test only to real rival submissions — which is what the protocol means. The full certificate is in uniqueness.json · validator.json · run card and is re-tested in tests/test_wbg5.py.

A shared-formula bug, found and fixed rather than worked around

The repository's forked metric module computed the break-even kernel credit for one extra dot as (a·DTI)/(1−a·DTI). That is wrong. Because the organizer weights satisfy 1−a−b = 0, one non-redundant dot moves the metric denominator by exactly a, so the true break-even is k > a·DTI — the value the frozen shared template in vendor/gems57 already used. The fork was corrected to match the template and is now pinned by tests/test_marginal_threshold.py, which derives the threshold from the metric instead of trusting the constant. Numerically the two agree to within 0.0033 in k (0.010 px), so no recorded result moves; the divergence is reported because an unnoticed fork of a shared evaluator is exactly the kind of drift that silently invalidates later work.

Two smaller irregularities: (a) the organizers' example_submission.tif is described as “total fault absence” but actually contains 1.0 on all 60,988 catalogue pixels — harmless, but it means the file cannot be used as a NaN/finite convention reference by description alone, only by inspection; (b) the earlier portal error “Predicted values must be in range [0, 1]” has no verified cause in any stored receipt, so it is treated as unresolved and avoided by matching the sample's exact convention.
