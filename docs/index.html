Why the GEMSDOE32 result cannot yet be explained

The competition's official metric rewards distance-tolerant overlap with expert-labelled faults. Its asymmetric weighting places greater cost on missed positives than on false positives, while the triangular distance kernel gives nearby predictions partial credit. A result can therefore reflect candidate coverage, line placement, confidence, and local geometry—not just a model family.

That is general metric interpretation, not a post-hoc explanation of this particular artifact. The result supplied in the request cannot be attributed to the “zeros” suffix or any mechanism without the exact raster, code/configuration, evaluation split/version, and an organizer receipt. Local evidence for all four is absent.

Can we beat it?

Possibly, but this checkout cannot establish that. The hidden/private test set is not available for local evaluation, so no honest local method can guarantee beating an organizer result. The only permissible pre-slot evidence here is the prescribed spatially blocked holdout, and its evaluator plus inputs are missing.

Safe next move: recover the official competition data through the authenticated data page, then reuse the shared evaluator/cache/writer and compare candidates under identical blocked splits. No weekly slot should be consumed by an unvalidated idea.

How to make a competition submission

  1. Obtain the official data. Download from the signed-in DrivenData data page and preserve the provided sample-submission raster and training features. This project has no authenticated download session or local copies.
  2. Run the shared spatial holdout. Hold out whole fault segments plus a buffer; derive catalogue-based features from visible faults only; mask visible faults exactly. Run pooled distance-weighted Tversky and report the evaluator version, withheld-positive count, and confidence interval. Test each feature alone for leakage first.
  3. Check originality and rationale. Compare surface rank-correlation and point overlap to all registry rasters, both pre-placement and final. A threshold crossing means log duplicate and stop. Keep the hypothesis, plausible non-fault mimic, code, inputs, and hashes.
  4. Write and validate one raster. Use the shared submission writer. Confirm EPSG:32611, matching shape/bounds/transform and 100 m grid, exactly one float32 band, finite probabilities in [0, 1] on footprint, no NaN in footprint, and null/NaN outside. Run the official submission page's file checks too.
  5. Only then make a separate selector decision. Promote only if it beats the current holdout best and complies with the competition's weekly cap. A valid file is not automatically a high-scoring file.
  6. Submit manually on DrivenData. Upload the validated .tif (or a zip containing that one GeoTIFF), add a unique descriptive name and a note of at most 140 characters, submit, then save the submission-page receipt. This repository does not automate or claim a submission.
