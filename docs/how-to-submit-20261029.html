How to submit · read the verdict first

No file is cleared to submit. The new candidate fails the leakage canary and the literal uniqueness rule. The historical files are not to be copied. Download the research file for inspection only.

  1. Read the verdict on the summary page. A file may be submitted only when its run card shows ok_to_submit: true. Currently none does.
  2. Check the file hash. Verify the SHA-256 against the run card before any upload.
  3. Format rules (problem page, rules PDF): one GeoTIFF, float32, EPSG:32611, 3730 × 3292, values in [0, 1]. The local validator checks this; it does not check acceptance.
  4. Name and note. Each submission needs a unique name and a note of at most 140 characters. The candidate's note is 135 characters.
  5. Limit. Three submissions per week (problem page). The remaining allowance is not visible from this sandbox.
  6. Upload is manual. It is done by the account owner on the official page: https://www.drivendata.org/competitions/306/competition-doe-gems/submissions/. This repository never stores or requests DrivenData credentials.
