01 / DO THIS

Submitting the file, step by step

Five minutes, no human review, no account changes on this page.

  1. Download the file — wbg5-satcov-morph-20261028-nanoutside.tif (or the .zip). Upload it as downloaded; the filename does not need to match the label.
  2. Open the submission page — drivendata.org/competitions/306/competition-doe-gems/submissions/.
  3. Choose the file under “File to submit”. A single-band GeoTIFF is accepted directly; the .zip also works and contains exactly one identical member.
  4. Name (the submission label, not the filename): wbg5-satcov-morph-20261028 — unique, unused in this competition, and traceable to this repository.
  5. Note (≤140 characters): satcov-morph-1: physics-only fault likelihood + spacing-constrained coverage dots (81 characters).
  6. Submit. The platform validates geometry, dtype and the [0, 1] range automatically and returns a score on the public leaderboard.
Why the earlier “Predicted values must be in range [0, 1]” error cannot recur here.

This file writes NaN only outside the study area — the exact convention of the organizers' own example_submission.tif, which also contains NaN there — and every finite value lies strictly inside [0, 1] (observed range 0.0–1.0). Archived peer receipts show both conventions scoring identically (e.g. the same dot set published as both -nan and -allfinite), so the convention is not what limits the score.

If the portal rejects the file anyway

Fall back to writing 0.0 outside the study area instead of NaN — the same dots, different exterior convention — with python scripts/submission_writer.py <prediction.npy> out.tif --outside zero. That variant keeps every value finite and stays inside [0, 1].
